Despliegue en Azure Container Apps

La app Angular corre como contenedor nginx. Los datos dejan de estar compilados en el bundle: un job mensual los escribe en Blob Storage y la app los lee al cargar. Actualizar datos ya no requiere reconstruir ni redesplegar.

Cambios necesarios en el repo

Aún no están implementados. Hoy data.service.ts importa los JSON de forma estática, por lo que quedan dentro del bundle.

DataService lee en tiempo de ejecución

// src/app/core/data.service.ts
- import costosData from '../../assets/data/costos.json';
- import aiCacheData from '../../assets/data/ai-cache.json';
+ readonly costos  = httpResource<CostosData>(() => '/data/costos.json');
+ readonly aiCache = httpResource<AiCache>(() => '/data/ai-cache.json');

Los computed() existentes leen costos.value(), y las vistas muestran un estado de carga mientras llega. En desarrollo, proxy.conf.json apunta /data a src/assets/data.

nginx.conf de costos-web

# /etc/nginx/templates/default.conf.template
location / {
  try_files $uri $uri/ /index.html;
}
location /data/ {
  rewrite ^/data/(.*)$ /data/$1?${DATA_SAS} break;
  proxy_pass https://${STORAGE_ACCOUNT}.blob.core.windows.net;
  proxy_set_header Host ${STORAGE_ACCOUNT}.blob.core.windows.net;
  proxy_ssl_server_name on;
  add_header Cache-Control "no-cache";
}

La imagen nginx:alpine sustituye STORAGE_ACCOUNT y DATA_SAS al arrancar. no-cache en /data/ hace que el mes nuevo se vea de inmediato, y los assets con hash se cachean un año.

Kimi mediante LLMHub en costos-etl

  • El contenedor del job instala la librería LLMHub (en scripts/requirements.txt) y accede a la API de Kimi a través de ella.
  • generate_ai_cache.py deja de llamar por requests al endpoint de Gemini y pide los 15 análisis a Kimi por LLMHub.
  • KIMI_API_KEY reemplaza a GEMINI_API_KEY: vive en Key Vault y llega al job como variable de entorno.

Política de horario laboral en costos-web

# scale de la Container App costos-web
minReplicas: 0
maxReplicas: 2
rules:
  - name: horario-laboral
    custom:
      type: cron
      metadata:
        timezone: America/Bogota
        start: "0 7 * * 1-5"
        end:   "0 19 * * 1-5"
        desiredReplicas: "1"

Solo se define la regla cron, sin la regla HTTP. Fuera de horario la app queda en 0 réplicas y no responde, y tampoco genera costo de cómputo. Ajusta las horas al horario laboral real.
