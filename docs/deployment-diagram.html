Despliegue en Azure: sitio estático, Function y Application Gateway

El build de Angular se publica como sitio estático en una Storage Account, y una Azure Function expone la API que entrega los datos. El Application Gateway es la única entrada y enruta cada petición a uno de los dos. El Container Apps Environment queda solo para el job mensual que actualiza los datos. Actualizar datos ya no requiere reconstruir ni redesplegar.

Cambios necesarios en el repo

Aún no están implementados. Hoy data.service.ts importa los JSON de forma estática, por lo que quedan dentro del bundle.

DataService lee la API en tiempo de ejecución

// src/app/core/data.service.ts
- import costosData from '../../assets/data/costos.json';
- import aiCacheData from '../../assets/data/ai-cache.json';
+ readonly costos  = httpResource<CostosData>(() => '/api/costos');
+ readonly aiCache = httpResource<AiCache>(() => '/api/ai-cache');

Los computed() existentes leen costos.value(), y las vistas muestran un estado de carga mientras llega. En desarrollo, proxy.conf.json apunta /api a la Function local (func start, puerto 7071).

Reglas del Application Gateway

# regla path-based del listener HTTPS
backend pools:
  static: <account>.z13.web.core.windows.net
  api:    costos-api.azurewebsites.net
url path map:
  /api/*  → api     (host header del backend)
  default → static  (host header del backend)

Las rutas de Angular (/resumen, /modelos…) no existen como archivos. En el sitio estático, index.html se configura también como documento de error 404, así un enlace directo carga la app y el router de Angular resuelve la vista.

Function costos-api

  • Estructura: endpoints/, modules/, services/, models/, schemas/, exceptions/, constants/, utils/.
  • GET /api/costos y GET /api/ai-cache leen el blob de data/ con DefaultAzureCredential (identidad administrada con rol de lectura de blobs).
  • Responde con Cache-Control: no-cache para que el mes nuevo se vea de inmediato. Los assets con hash de $web se cachean un año.

Kimi mediante LLMHub en costos-etl

  • La imagen del job instala requirements.txt y requirements-llmhub.txt. llmhub_uniandes sale del feed privado de Azure Artifacts.
  • etl/costos_etl/llm.py pide los 15 análisis a Kimi a través de LLMHub (LLM_PROVIDER=llmhub).
  • keyvault.py lee la clave y el endpoint del modelo en Key Vault por nombre de secreto (LLM_SECRET_API_KEY, LLM_SECRET_ENDPOINT).
